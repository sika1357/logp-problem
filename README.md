# logp-problem

An Everglades eval task (inverse, computational chemistry) built with the `everglades-author`
skill: given three HPLC "archives" of chromatographic data and a real oracle instrument, infer
the octanol/water log P of an unknown drug candidate.

**Status: calibration gate green, exported, not yet pasted into RLS.**

## What it tests

Three candidate structures from the same benzamide-piperazine series (differing only in a
para-halogen: Cl / Br / F) were each run through a full RP-HPLC characterization on a separate
column - the resulting datasets are `archive_A`, `archive_B`, `archive_C`. Exactly one archive
holds `candidate_1`, the one whose log P is graded; the other two are matched-control runs on
the other two candidates.

The model must:
1. Use RDKit to compute each candidate's exact mass from its disclosed SMILES.
2. Query the oracle's `spectroscopy` mode (a real high-resolution [M+H]+ mass reading) to match
   which archive is `candidate_1` - **not** by guessing which archive's eventual number looks
   like a plausible drug (the prompt states log P 1.0-5.0 as background color and explicitly
   warns against using it for identification).
3. Query `chromatography` for the correct archive's raw injection log, exclude the archive's
   unflagged invalid entries (out-of-window mobile-phase runs, physically-impossible retention
   times), average duplicate injections, void-time-correct, and extrapolate each compound's
   retention across mobile-phase composition to the water limit (Snyder/Soczewinski
   linear-solvent-strength model - the real basis of the OECD Test Guideline 117 HPLC method for
   determining log P).
4. Regress the extrapolated quantity against the calibration panel's known log P values and
   invert for the unknown.

**Golden answer:** 4.617 (tolerance 0.05 absolute). **Primary trap / near-miss:** picking the
archive by plausibility instead of the mass match lands on 2.761 - a clean, self-consistent,
wrong number (confirmed via `solution/shortcut.py`, ~37x tolerance off).
